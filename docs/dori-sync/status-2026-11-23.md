## Open items

### 1. Live ChatGPT smoke (`-p` on chatgpt-subscription)

Not run. The ChatGPT tokens seeded from the owner's `~/.omo/agent/auth.json` had expired, and a turn would have
refreshed them. A refresh rotates the refresh token, which would sign the owner's real omo out. mhc must have its own
ChatGPT login instead:

1. Open mhc in its shadow HOME: `scripts/dori/mhc-dori.sh` (interactive; the shadow HOME is `~/.maho/home`).
2. Drop the seeded copies of the owner's ChatGPT accounts first, so mhc never selects or refreshes them:
   `/gpt-account list`, then `/gpt-account remove <id>` for each seeded account. Use `remove` (local only); never
   `signout`, which revokes the session remotely and would sign the owner out.
3. Run `/login chatgpt-subscription` and finish the browser sign-in. This records the SD-4 consent too. If it does
   not, run `scripts/dori/mhc-dori.sh auth consent chatgpt-subscription --yes` (this writes only the shadow
   `settings.json`).
4. Run the smoke: `scripts/dori/mhc-dori.sh --no-session --model chatgpt-subscription/gpt-6.1-sol -p 'Reply with exactly: OK'`.
5. Do not re-seed `~/.maho/home/.omo/agent/auth.json` from the real file afterwards; that would bring the owner's
   tokens back.

## omarchy setup

- Checkout: `~/work/mhc` (fork `Momentum96/mhc`, branch `dori/compat-20261122`).
- Upstream clones: `~/work/upstream/senpi` and `~/work/upstream/oh-my-openagent` (full history and tags). The pinned
  senpi checkout is `~/work/upstream/senpi-pin`; every test run sets `SENPI_SRC=$HOME/work/upstream/senpi-pin`.
- Disks: `~/work` is on a slow HDD. Build output goes to the NVMe at `/mnt/nvme-work`: each checkout's or worktree's
  `target` is a symlink to `/mnt/nvme-work/targets/<name>` (roadmap.md rule 6).
- Cargo lock: several agents build at once, so every cargo command runs as
  `flock $HOME/work/.mhc-cargo.lock cargo ...`.
- Linux packaging needs the host glibc as the ceiling: `MHC_GLIBC_CEILING=2.44` on both the package and the
  `--verify-only` command (roadmap.md, "Repackage on omarchy").
- Claude consent: `providerRiskConsent.anthropic-subscription` is recorded only in the shadow HOME
  (`~/.maho/home/.omo/agent/settings.json`), never in the real `~/.omo`.
